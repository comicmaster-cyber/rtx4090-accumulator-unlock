# 02 — 아키텍처 노트 (고수준)

> 이 문서는 **개념 설명**입니다. 구현 코드/목표값/서명 처리/자산 생성법은 이
> 문서에 없습니다. 재현 절차는 `docs/05-IMPLEMENTATION.ko.md`가 공개 업스트림을
> 가리키는 방식으로 제공합니다. 재현은 독자의 책임이며, 법적 리스크는 별도로
> 검토해야 합니다.

## 1. 알려진 것

- FP16 누산 경로는 피크의 99%까지 나옵니다.
- FP32 누산 경로만 피크의 약 50%입니다.
- 전력·클럭·온도·드라이버 커널 선택의 문제가 아닙니다.
- 이 상태는 **OS 드라이버가 바인딩되기 전**, 부팅 초기에 확정됩니다.
- 전원을 끄면 상태가 다시 초기화됩니다.

## 2. 개념 모델

GPU는 부팅 시 내부적으로 **속도 셀렉터(speed selector)** 와 **권한 수준(permission
level)** 을 확정합니다. 이 값은 이후 드라이버가 그대로 사용합니다. 관찰된 카드에서는
이 초기 상태가 FP32 누산 경로를 절반으로 제한하는 조합으로 래치되어 있습니다.

개념적으로 이 상태를 바꾸려면:

1. **드라이버 로드 이전**에 실행되는 UEFI 구성 요소가 필요합니다.
2. 해당 구성 요소는 벤더의 부팅 펌웨어 체인(펌웨어 로딩·검증)과 **협조**해야 합니다.
3. 상태를 덮어쓴 뒤 **정확히 한 번의 디바이스 리셋(FLR)** 을 수행해, 드라이버가
   깨끗한 상태에서 시작하도록 해야 합니다.
4. 이후 GOP/디스플레이를 복구하고 Windows로 핸드오프합니다.

## 3. 왜 어려운가

- 펌웨어 인증/서명 체계와 권한 수준을 이해해야 합니다.
- WPR(Wipe Protected Region) 메모리 레이아웃과 부팅 순서를 맞춰야 합니다.
- 리셋/핸드오프 순서가 틀리면 화면이 검게 멈추거나 디바이스가 불안정해집니다.
- 실패 시 복구는 **물리 전원 차단**뿐입니다.

## 4. 검증 기준 (값 없이)

성공은 다음이 모두 확인되어야 합니다.

- 변경 후 셀렉터 상태를 **다시 읽어** 의도한 상태인지 확인
- **FLR이 정확히 1회**
- DMA/quiescence 정리, 버스 마스터링 해제
- GOP/디스플레이 복구, Windows 정상 부팅
- `tools/benchmark`에서 `f32acc`가 `f16acc`에 근접

측정 없이 "성공"이라고 판단하지 마세요. 로그 한 줄이나 화면 복구만으로는 부족합니다.

## 5. 휘발성

- 상태는 전원 인가 시 다시 확정됩니다.
- 재부팅/전원 차단 후에는 다시 적용해야 합니다.
- 따라서 "영구 패치"가 아니며, vBIOS 플래시와도 다릅니다.

## 6. 이 저장소의 범위

포함:
- 관찰/측정 (`docs/01`, `tools/benchmark`)
- 읽기 전용 콜드 상태 캡처 (`tools/probe`)
- 캡처 요약 (`tools/derive_profile.py`)
- 카드 식별/해시 (`profiles/observed.json`)

의도적으로 제외:
- 펌웨어 실행/인증 처리 코드
- 셀렉터/권한 쓰기 코드와 목표값
- 자산 생성기, EFI, 부팅 매체 제작 도구 (재현 가이드는 `docs/05`)
