# 01 — 관찰: FP32 누산 경로만 절반

## 1. 현상

레퍼런스 카드(RTX 4090 24GB, AD102-300)에서 `mma.sync` 처리량을 누산기 종류별로
측정한 결과:

| 경로 | 실측 | 이론 피크 대비 |
|---|---|---|
| FP16 → FP16 acc | 353.8 TFLOPS | 99.4% |
| FP16 → FP32 acc | 182.9 TFLOPS | 49.6% |
| BF16 → FP32 acc | 182.7 TFLOPS | 49.6% |
| TF32 → FP32 acc | 91.4 TFLOPS | 49.6% |

- 부하 중 **P2, 2805 MHz, 162 W**
- `clock64()` 실측 SM 클럭 2686 MHz
- 비텐서 FP32 처리량은 정상

즉 **텐서 코어 자체는 정상이고, FP32 누산 경로만 피크의 약 50%**입니다.
PyTorch/cuBLAS의 기본 경로가 FP32 누산이므로 실사용에서 약 2배 손해가 납니다.

## 2. 측정 방법

- `tools/benchmark/accum.cu` — `mma.sync` raw 루프, 128 SMs, 1024 blocks × 256 threads
- `f32acc` / `f16acc` / `bf16`을 같은 루프 구조로 비교
- 워밍업 후 5회 측정, 최고값 사용
- cuBLAS `cublasGemmEx` n=4096 보조 측정

## 3. 상세 결과

### Raw MMA

| 경로 | 언락 전 | 상태 변경 후 | 배율 |
|---|---|---|---|
| FP16 → FP32 acc (chains=8) | 182.9 | 353.7 | 1.93× |
| FP16 → FP32 acc (chains=1) | 182.3 | 333.7 | 1.83× |
| BF16 → FP32 acc (chains=8) | 182.7 | 354.4 | 1.94× |
| TF32 → FP32 acc (chains=8) | 91.4 | 176.9 | 1.94× |
| FP16 → FP16 acc (chains=8) | 353.8 | 358.6 | 1.01× |

### cuBLAS GEMM (n=4096)

| 모드 | 언락 전 | 상태 변경 후 | 변화 |
|---|---|---|---|
| FP32 pedantic (비텐서) | 54.8 | 54.9 | 0% |
| FP16 / FP32 acc | 162.9 | 216.1 | +33% |
| BF16 / FP32 acc | 154.0 | 156.1 | +1% |
| TF32 / FP32 acc | 88.8 | 150.5 | +70% |

n=8192 (상태 변경 후, 참고): FP32 55.6 / FP16 183.0 / BF16 189.8 / TF32 146.1.

### 안정성

- 31초 연속 FP32 누산 부하: 최저 330.2, 중앙값 333.3 TFLOPS
- 온도 60°C, 전력 ~215 W, WHEA 오류 0건

## 4. 해석

- 전력·클럭·온도 문제가 아닙니다. 피크 클럭에서 피크의 99%가 나오는 경로(FP16 acc)와
  절반만 나오는 경로(FP32 acc)가 공존합니다.
- 전력이 200 W대인 것은 정상입니다. 텐서 전용 루프는 450 W TGP를 모두 쓰지 않습니다.
- cuBLAS 수치는 shape·커널·클럭에 따라 달라집니다. 하드웨어 판정은 raw MMA가 기준입니다.
- 애플리케이션(ComfyUI/PyTorch) 수준 가속은 워크로드에 따라 다르며 보장하지 않습니다.
